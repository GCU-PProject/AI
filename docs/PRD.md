### 5-2. 법률 모아보기 (삭제)

- **입력:** 국가, 분야, 키워드
- **출력:** 관련 법령 목록 + 주요 조항 요약
- **구조:**
    - Spring → 사용자 요청 처리 / 페이징 / 즐겨찾기
    - FastAPI → 검색어 기반 법령 요약/추천 (벡터 검색 + LLM)
- 참고
    - 사용자가 직접 법령 검색(키워드 검색) / 국가·분야 필터(추가기능) / 본문 열람 → DB 조회
    - 법률 DB 구축(AI 쪽에서 처리)
        - 데이터: 세계법제정보센터, 국가법령정보센터, 각국 정부 공개 법률 API/크롤링
        - 전처리
            - 조항 단위로 분리 (chunking)
            - 국가별 벡터 임베딩 생성 (ex. `law_embeddings`)
            - 메타데이터(국가, 분야, 법령명) 포함한 벡터 스토어 구축
    - 앞으로 Rag 돌릴 때 이 데이터 활용
- Spring 기능
    - 모든 법률 get (페이징 포함)
    - 법률 상세 조회 get (국가/주제로 페이지별로 만들고 그 페이지 안에 제0항, 제0조 표시)
    - 검색 (키워드 입력 → 조회) get
    - 북마크(저장) post
    - 북마크 해제 delete
- AI 기능
    - 데이터 수집 : 세계법제정보센터, 국가법령정보센터, 각국 정부 공개 법률 API/크롤링 (필요 시 OCR 사용)
    - 전처리
        - 수집 데이터를 국가, 법령, 조항 단위로 chunk 분리
        - 정제된 데이터 임베딩 (임베딩 모델은 미정)
        - 사용자가 질문 입력 시 질문을 임베딩하여 가장 가까운 벡터 법률 제공
    - DB 저장
        - 국가별 → 주제별 → 제0항, 제0조 별로 DB 저장
            - URL 필드 포함 (Spring 쪽이랑 맞춰야 함)
            - 추후 RAG에 활용
            
            | **컬럼명** | **데이터 타입** | **설명** |
            | --- | --- | --- |
            | `law_id` | `BIGINT` (PK) | 법률 조항 고유 ID |
            | `country_code` | `VARCHAR` | 국가 코드 (예: "US", "KR", "TH") |
            | `law_title` | `VARCHAR` | 법령명 (예: "도로교통법") |
            | `category` | `VARCHAR` | 법률 분야 |
            | `article_no` | `VARCHAR` | 조항 번호 (예: "제3조 제1항") |
            | `content` | `TEXT` | 조항 본문 내용 |
            | `source_url` | `VARCHAR` | 법령 원문 출처 URL |
            | `last_updated` | `TIMESTAMP` | AI가 마지막으로 업데이트한 날짜 |
    - 법령 검색 : 사용자가 자연어? 키워드?로 검색하여 임베딩하여 가까운 벡터 법률 제공
        - request
            - keyword : 사용자가 입력한 키워드
            - country_code : 국가 필터 할 경우(선택사항)
        - response
            - law_id : 관련 법률 조항 고유 ID

### 5-3. LLM 기반 법률 QnA 챗봇

- 입력 옵션 : 자연어 텍스트 입력
- 출력 : LLM 요약 답변, 근거 조항, 출처
- 행동 : ~~다시 질문(수정)~~, 다른 답변 요구, ~~공유~~
    - 답변 하면서 어떤 법률이랑 연결되는지, 관련 법률 페이지랑 연결되는 url도 같이 전달
        
        → 챗봇 답변 저장이 아닌 법률 페이지에서 법률 저장으로 수정 → 저장 로직 1개로 줄어듦
        

- Spring 기능
    1. 질문 post
- AI 기능
    - 답변 생성 : 사용자의 질문(query)을 받아서 RAG를 통해 답변(answer)과 근거 법률(law_id)을 제공
        - request
            1. query : 사용자가 입력한 자연어 질문
            2. user_id : 사용자 식별 id, 필요 시 사용
        - response
            1. answer : LLM이 요약한 최종 답변
            2. law_id : DB에 저장된 법률 조항 고유 ID
    - 다른 답변 생성 (spring 쪽에서는 처음 질문이랑 똑같은 api로 요청 들어갈 예정 → FastAPI에서 분기처리 필요)

### 5-4. 국가 간 법률 비교

- 입력 : 주제 + 국가 2개
- 출력 : 특정 법률 주제(ex. 음주운전 처벌)에 대해 두 국가의 핵심 내용을 하이라이트 처리해 시각화하여 제공
- 행동 : 비교 조합 저장
    
    → 전부 저장하면 DB에 너무 많고 중복되는 데이터가 저장됨 → 비교 조합만 저장해두고 mypage에 get요청으로 조회만 되도록 해두면 → 프론트 쪽에서 클릭 시 비교 페이지로 이동해서 칸이 자동으로 채워지도록 처리 → 똑같이 조회 로직 수행 방식이 효율적일 듯?
    
    → 아니면 아예 빼는 게 더 좋을 수도
    

- Spring 기능
    - 질문 post
    - 비교 조합 저장 post (중복 방지 포함)
    - 비교 조합 삭제 delete → mypage에서 관리
- AI 기능 (여긴 대충 적어둠 → AI 담당이 수정 필요)
    - 비교 답변 생성 : 특정 주제와 두 국가를 받아서, 각 국가의 관련 법령을 RAG로 검색 및 요약하고, 두 법률의 공통점과 차이점을 비교 분석하여 제공
        - request
            - topic : 비교하려는 주제
            - country_code_1 : 첫 번째 국가 코드
            - country_code_2 : 두 번째 국가 코드
        - response
            - country_1_result : 첫 번째 국가 결과
                - law_id_1 : DB에 저장된 법률 조항 고유 ID
                - summary_2 : llm이 요약한 첫 번째 국가 법률 핵심 내용
                - highlight_keywords_1 : 핵심 키워드 목록
            - country_2_result : 두 번째 국가 결과
                - law_id_2 : DB에 저장된 법률 조항 고유 ID
                - summary_2 : llm이 요약한 첫 번째 국가 법률 핵심 내용
                - highlight_keywords_2 : 핵심 키워드 목록
            - compare_summary : 비교 분석 결과
                - common : 공통점
                - diff : 차이점
    - 하이라이트
        - 1안: LLM 기반으로 강조어 추출해서 보내면 프론트 쪽에서 하이라이팅 처리

### 5-5. 해외 이슈 대시보드 

- **입력:** 해외 법률 뉴스·정책 변경·국제 판례 데이터 크롤링
- **출력:** 최근 개정 법률(세계법제정보센터 api 사용할 수 있으면..), 이슈 기사
    - 사이트 몇 개, 키워드 몇 개만 정해서 ai 쪽에서 키워드 유사도 확인하고 이에 맞는 활동만 크롤링 하도록 설정해야 할 듯

→ 하려면 대시보드에 특정 기사 제목만 나타내고, 클릭 시 해당 기사 링크로 연결되도록 처리해야 할 듯

→ 단, 온보딩에서 받은 사용자 관심 국가로 한정해서 나타나도록 처리

- Spring 기능
    - 기사 조회 get (기사 제목, 국가, 날짜, 링크 정도만)
        
        → 클릭 시 링크로 이동하도록 프론트 쪽에서 처리
        
- AI 기능 (여긴 대충 적어둠 → AI 담당이 수정 필요)
    - 데이터 수집 : 주기적 크롤링을 통해 데이터 수집
    - 전처리 :
        - 사전에 정의된 핵심 키워드 및 임베딩 벡터를 통해 관련 없는 기사는 버림
        - 국가 태깅
        - 제목, 원문 링크, 발행일, 출처 등 필요한 데이터만 추출
    - DB 저장
        - 국가별로 DB저장 (issue 테이블)
            
            
            | **컬럼명** | **데이터 타입** | **설명** |
            | --- | --- | --- |
            | `issue_id` | `BIGINT` (PK) | 기사 고유 ID |
            | `country_code` | `VARCHAR` | 국가 코드 (예: "US", "KR", "TH") |
            | `title` | `VARCHAR` | 기사 제목  |
            | `source_name` | `VARCHAR` | 출처  |
            | `source_url` | `VARCHAR` | 원문 기사 링크 |
            | `published_at` | `TIMESTAMP` | 기사 발행일 |
            | `last_updated` | `TIMESTAMP` | AI가 마지막으로 업데이트한 날짜 |
