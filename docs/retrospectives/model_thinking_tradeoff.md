# 생성 모델 선정 — RAGAS 비교 실험과 추론 트레이드오프

> 2026-06-10 | 분야: 모델 | 생성 모델 최종 선정 근거

## 실험 설계 — 고정 변수

모델 비교의 전제는 변수 통제다. 모든 실험에서 다음을 고정했다.

| 항목 | 고정값 |
|------|--------|
| 평가셋 | 30문항 (seed 조항 기반 합성, 4개 주) |
| 채점 LLM | gemini-3-flash-preview, thinking off |
| 임베딩 | Qwen3-Embedding-0.6B (자체 호스팅) |
| 생성 파라미터 | temperature=0, max_tokens=4096, top_k=20, top_p=0.7 |
| 검색 | top_k=5, L2 threshold 0.90 |

비교 대상 모델: gemini-3-flash-preview, 3.1-pro, 3.1-flash-lite, 3.5-flash (+RAG 미적용 baseline)

## 1라운드 — 모델별 기본 설정 비교

| 실험 | ContextRecall | ContextPrecision | Faithfulness | FactualCorrectness | 평균 총응답 |
|------|------|------|------|------|------|
| baseline (RAG 없음) | - | - | - | 0.3923 | 7.40s |
| 3-flash | 0.9083 | 0.8472 | 0.7578 | 0.4590 | 19.29s |
| 3.1-pro | 0.9000 | 0.8674 | 0.7208 | 0.5733 | 23.62s |
| 3.1-flash-lite | 0.8833 | 0.8318 | 0.7187 | 0.5143 | 10.56s |
| 3.5-flash | 0.9250 | 0.8428 | 0.7363 | 0.4860 | 19.18s |

관찰:

- RAG 적용으로 FactualCorrectness가 baseline 대비 전 모델에서 상승 (0.39 → 0.46~0.57). **RAG 도입 효과 확인.**
- 응답시간 19~24초는 서비스로 부적합. 단계별 측정 결과 thinking 토큰이 생성 시간의 절반 이상을 차지.

## 2라운드 — thinking_level=low

thinking 지원 모델(3-flash, 3.1-pro, 3.5-flash)에 `thinking_level="low"`를 적용했다. lite 모델은 thinking 기능 자체가 없어 해당 없음.

| 실험 | Faithfulness | FactualCorrectness | 총응답 (default 대비) |
|------|------|------|------|
| 3-flash_low | 0.7841 | 0.4637 | 17.41s (-1.9s) |
| 3.1-pro_low | 0.7460 | 0.5937 | 17.70s (-5.9s) |
| 3.5-flash_low | 0.7722 | 0.5183 | 13.03s (-6.2s) |

**반직관적 발견: low로 낮추면 속도뿐 아니라 품질(FC)도 전 모델에서 같거나 오른다.** 명확한 답이 있는 법률 Q&A에서 과도한 추론이 오히려 노이즈를 만드는 것으로 해석된다. → default 설정은 전부 탈락, low 이하만 후보로 유지.

## 3라운드 — 번역 모델 고정 후 재측정 (_tr)

이 시점까지 번역을 생성 모델이 겸하고 있어, 검색 지표(CR/CP) 차이가 "모델의 검색 활용 능력"이 아니라 **"모델의 번역 품질"**을 측정하고 있었음을 발견했다. 번역을 Cloud Translation LLM으로 분리·고정하고 후보 3개를 재측정했다.

| 실험 | CR | CP | Faithfulness | FactualCorrectness | 총응답 |
|------|------|------|------|------|------|
| 3.1-flash-lite_tr | 0.8917 | 0.8228 | **0.7590** | 0.5127 | **8.27s** |
| 3.5-flash_low_tr | 0.8917 | 0.8228 | 0.7190 | 0.5600 | 11.50s |
| 3.1-pro_low_tr | 0.8917 | 0.8228 | 0.7035 | **0.5643** | 13.71s |

- **CR/CP가 전 모델 동일** — 번역이 같으면 검색 결과가 같으므로 당연한 결과이며, 번역 분리가 제대로 됐다는 검증이기도 하다. 이후 모델 비교는 Faithfulness와 FC로만 한다.
- 3.1-pro_low와 3.5-flash_low의 FC 차이는 0.0043으로 노이즈 범위. 품질이 같다면 2.2초 느린 3.1-pro는 탈락.

## 추가 검증 — 추론 완전 비활성화 (thinking_budget=0)

3.5-flash의 thinking을 완전히 끄면 lite급 속도가 나오는지 확인했다.

| 실험 | Faithfulness | FactualCorrectness | 총응답 |
|------|------|------|------|
| 3.5-flash_none_tr | 0.7537 | 0.5147 | 9.45s |

품질이 3.1-flash-lite와 사실상 동일해졌다(Faith 0.754 vs 0.759, FC 0.515 vs 0.513). 같은 품질을 1.2초 느리게 내므로 none 구성 자체는 탈락 — 하지만 이 결과가 아래 패턴을 완성했다.

## 발견 — 추론 강도에 따른 일관된 역방향 패턴

_tr 실험 4개를 추론 강도 순으로 정렬하면 두 지표가 거의 단조롭게 반대로 움직인다.

| 추론 강도 | 모델 | Faithfulness | FactualCorrectness |
|----------|------|-------------|--------------------|
| 없음 | 3.1-flash-lite | **0.759** | 0.513 |
| 없음 (budget=0) | 3.5-flash | 0.754 | 0.515 |
| low | 3.5-flash | 0.719 | 0.560 |
| low | 3.1-pro | 0.704 | **0.564** |

해석 — **추론은 모델을 검색된 조항 "밖으로" 나가게 한다:**

- 추론 없음 → 검색된 조항을 거의 그대로 옮기는 보수적 답변. 모든 문장이 컨텍스트로 검증됨(Faithfulness↑), 조항에 없는 정답 요소는 못 채움(FC↓)
- 추론 있음 → 조항을 해석하고 자체 지식으로 보충한 풍부한 답변. 기준 정답과 더 일치(FC↑), 검색 근거로 검증 안 되는 문장 증가(Faithfulness↓)

두 지표는 같은 현상(자체 지식 개입)의 양면이며, 추론 강도가 그 개입량을 조절한다.

## 결정 — 근거충실도 우선, gemini-3.1-flash-lite 선택

법률 정보 서비스에서 두 가치가 충돌할 때:

- 사실정확도 우선 = "자주 맞지만 출처를 검증할 수 없는 답변"
- 근거충실도 우선 = "제시한 법령 조항으로 검증 가능한 답변"

법률 도메인에서 검증 불가능한 주장은 맞더라도 위험하다(사용자가 답변을 근거로 행동할 수 있고, 자체 지식은 법 개정 이후 정보가 틀릴 위험을 내포한다). **근거충실도를 우선하여 Faithfulness 최고(0.759) + 최속(8.27s)인 gemini-3.1-flash-lite를 선택했다.**

## 해석 시 주의 (한계)

- 30문항 합성 데이터셋에서 0.03~0.05 차이는 노이즈 범위일 수 있다. 단일 비교가 아닌 4개 구성의 **일관된 단조 패턴**이기에 신뢰했다.
- FactualCorrectness는 합성 reference(짧고 간결, 44~288자)와 비교하므로 간결하게 답하는 모델에 유리한 편향이 있다. 절대 점수가 아닌 상대 비교로만 해석한다.
- 검색 지표(CR/CP)는 번역·검색이 고정된 비교에서는 모델 간 차이를 보여주지 못한다. 검색 전략(top_k, 하이브리드 등)을 바꿀 때만 유효하다.
- 이 비교는 풀스캔 벡터 검색 기준 측정이다. 이후 HNSW 인덱스를 도입했으므로(`search_db_vector_index.md` 참고) 최종 구성에서는 선정 모델을 동일 조건으로 재측정한다.

## 배운 점

- 추론(thinking)은 "켜면 좋은 것"이 아니다. 근거 기반 답변이 목적인 RAG에서는 추론이 오히려 컨텍스트 이탈을 유발한다.
- 지표 하나가 오르면 왜 올랐는지 메커니즘을 설명할 수 있어야 한다. FC 상승의 원인이 "조항 밖 지식"임을 모르고 봤다면 반대 결정을 했을 것이다.
- 평가 변수(번역)를 고정하자 숨어 있던 패턴이 드러났다. 통제 없는 비교는 패턴을 가린다.
