# 번역 모델 분리 — Cloud Translation LLM 채택

> 2026-06-10 | 분야: 모델 | 적용 완료, 자체 평가 검증 완료

## 배경

법령 데이터와 검색 대상은 영어, 사용자 질문은 한국어다. 검색 전 질문을 영어로 번역해야 하는데, 기존에는 답변 생성용 Gemini 모델을 번역에 재사용했다. 두 가지 문제가 있었다:

1. **속도**: 범용 LLM 번역이 2~7초를 차지 (모델에 따라 다름, 3.1pro는 5초+)
2. **실험 통제**: 생성 모델을 바꿀 때마다 번역 품질도 같이 바뀌어, 검색 지표(ContextRecall/Precision) 변화가 모델 차이인지 번역 차이인지 구분 불가

## 후보 선정

- [Alconost 2025~2026 번역 엔진 평가](https://alconost.com/en/blog/best-llm-for-translation-2026): Gemini가 전체 AQI 1위(77.7), 법률 콘텐츠 1위(84.6) → Gemini 계열 우선 검토
- [Google 공식 모델 비교](https://docs.cloud.google.com/translate/docs/advanced/compare-models): `general/translation-llm`은 Gemini 기반 번역 특화 미세조정 모델, "Highest quality translation model", Gemini 2.0 Flash 대비 2배 빠른 지연시간

번역 전용 리더보드(품질+비용+속도를 한눈에)는 존재하지 않아, 외부 평가로 후보를 좁히고 자체 평가로 검증하는 방식을 택했다.

## 결정

**Google Cloud Translation LLM (`general/translation-llm`)** 채택.

- 번역에 특화 미세조정된 Gemini 기반 모델 (범용 모델 대비 빠르고 품질 동등 이상)
- GCP 기반 인프라라 IAM/과금 체계 그대로 활용
- 적용 범위: **검색용 질문 번역에만** 사용. 답변 생성에는 원본 한국어 질문 전달

## 검증 결과 (30문항 자체 평가)

| 항목 | 변경 전 (Gemini 범용) | 변경 후 (Translation LLM) |
|------|---------------------|--------------------------|
| 평균 번역 시간 | 2.1~7.1s (모델별 상이) | **~0.5s** |
| ContextRecall | 0.875 | 0.8917 (유지) |
| ContextPrecision | 0.8575 | 0.8228 (유지, 노이즈 범위) |
| 실패율 | 0% | 0% |

번역 시간 약 -76%, 검색 품질 유지. **부수 효과로 평가 체계도 개선**되었다 — 번역이 고정되니 모든 생성 모델이 동일한 검색 결과를 받아, 검색 지표와 생성 지표가 완전히 분리됐다.

## 배운 점

- 파이프라인의 각 단계는 그 작업에 특화된 모델을 쓰는 게 속도·통제 양면에서 낫다. "한 모델로 다 하기"는 편하지만 실험 설계를 오염시킨다.
- 외부 벤치마크가 없으면 "외부 근거로 후보 압축 → 자체 평가로 검증" 2단계가 현실적인 선정 방법이다.
